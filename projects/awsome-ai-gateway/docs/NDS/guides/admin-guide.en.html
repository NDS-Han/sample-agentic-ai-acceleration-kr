Operating workflow

Start from the affected app, user, team, or model. Use the table to find the relevant screen and identify what to verify before making a change.

TaskWhere to startWhat to verify
Onboard a userSign-in and Users/TeamsTeam, role, and effective app and model access.
Roll out a modelModel Management, then App PolicyAlias, active status, pricing units, client routing, and effective access for the intended users.
Control spendDashboard and Budget ManagementApp, reporting period, budget scope, and enforcement policy.
Connect a clientCLI for interactive users or Agents and Integration for server-side applicationsCredential flow, gateway URL, model alias, and permitted app.
Investigate an incidentMonitoring, Analytics, and Audit LogRequest ID, time window, affected scope, and related administrative actions.

Before saving a change, confirm that you are in the intended environment and verify the scope and target. After saving, reopen the affected screen and check the effective setting or status. Use Audit Log to check the corresponding administrative event when one is recorded.

Sign-in and access

The development console redirects to the Cognito sign-in page. A successful administrator sign-in opens Dashboard.

Sign in

  1. Open the development administrator console.
  2. Enter your assigned account in Email address and Password.
  3. Select Sign in. Confirm that Dashboard and the administrator menus appear.

Reset your password

  1. Select Forgot your password? on the sign-in page.
  2. Enter your account email and select Reset my password.
  3. Use the emailed code and follow the prompts to set a new password. Select Back to return to sign-in if needed.

If you see User registration failed, check the account’s identity-provider group assignment and gateway registration. For 403, check that the signed-in account has the role required by the page. Team leaders and developers see menus for their roles. Use Logout in the console header when you finish.

Dashboard

Read cost, budget, and usage

Dashboard summarizes cost, budget utilization, request activity, and usage distribution for the selected app and period.

  1. Use All for the overall view or select Claude Code, Cowork, Codex, or Other to isolate an app.
  2. Choose This month, Last month, or Select period. Use the displayed time zone and refresh timestamp when comparing two views. The captured dashboard shows monthly boundaries in IST.
  3. Review cost and budget cards alongside total requests, errors, and token usage. Use About web search pricing to see how web search contributes to the displayed cost.
  4. Use the distribution view to identify the largest contributors. If the chart offers a Scope selector, choose a team to narrow the comparison. Open Analytics for a more detailed breakdown.

Users/Teams → Organization tree

Manage organization, team, and user access

The organization tree lets you find a member, inspect policies at the relevant scope, and see the access that applies to that user.

Find the account or team

  1. Open Users/Teams. Expand the organization, department, and team, or use Search organization.
  2. Select a team to view its membership, leader, access, and limits. Use Change leader when you need to assign or update the team leader.
  3. Select a user to inspect the user’s role, organization assignment, and policy detail. Open Show full model × app table to inspect the effective combinations.

Review or change a policy

  1. Choose the scope that matches the intended audience. Organization-wide settings can affect multiple teams.
  2. Open Change beside App access, Allowed models, or Rate limit where the control is available.
  3. Compare the inherited and configured values. Verify the unit and intended limit before saving. Reopen the user detail and check the effective policy after a change.

Force re-authentication for team can revoke active keys for team members. Review the target and member count in the confirmation dialog before proceeding. Sync Cognito updates gateway records from the identity source, so verify that you are using the intended environment before running it.

Model Management

Manage the model catalog and pricing

The catalog lists the gateway aliases available to configure for apps and users. Expand a row to verify the provider, upstream model ID, context, and detailed pricing.

Register or update a model

  1. Select Add model and choose the deployment’s provider. Complete the fields shown for that provider.
  2. Check the model ID, client-facing alias, context and output limits, endpoint where applicable, and price units. The pricing form presents rates in USD per million tokens.
  3. For an existing alias, use Edit from the model row. After saving, expand the row and verify the values. If the rollout requires user access or a default route, also check App Policy and the user’s effective policy.

Review pricing changes

  1. Open Sync Pricing and select an available source.
  2. Preview the changes. Review matched aliases, proposed rates, and any model specification changes shown in the comparison.
  3. Confirm which aliases are selected before applying. Reopen the affected rows to verify the resulting values.

Deactivate stops new requests to the alias. Review defaults, fallback routes, and dependent apps before confirming. Delete removes the catalog entry and linked configuration such as pricing history, allow lists, rate limits, or downgrade references. Review the confirmation dialog before entering the alias.

App Policy → Claude Code, Cowork, or Codex

Configure policy for each client

App Policy groups client defaults, model access, web search, and routing controls by app.

  1. Select the client tab. Confirm the selected app before reviewing or changing any setting.
  2. Review the default model and routing settings. Open the default-model help when you need to confirm when the default is used.
  3. Inspect model access and the users covered by the policy. Review the web-search setting separately if the app uses that capability.
  4. Apply a change at the intended scope and verify the user’s effective app and model access in Users/Teams. Use a representative client request if you need to confirm routing behavior.

Budget Management

Set budgets and web-search quotas

Budget Management shows team and member usage and provides settings for monetary limits, enforcement, and web-search quotas.

Set or review a monetary budget

  1. Find a team and review usage against its configured limit. Use Set Budget at team level or expand the team and use the member’s Set Budget.
  2. Check the applicable limits, policy, and alert thresholds in the form. Review per-app limits when the budget needs to distinguish Claude Code, Cowork, and Codex.
  3. For multiple members of one team, open Bulk edit member budgets and verify the selected rows before saving.
  4. Reopen the team or member to confirm the saved amounts. A member limit above the team limit still leaves the team limit in effect.

Set or review a web-search quota

  1. Find Web search quota and select Set limit for the organization or the applicable team pool.
  2. For a user exception, go to User overrides, search for the member, and open the result.
  3. Check the scope and the quota units shown in the form. After saving, verify the target and resulting limit in the same view.
Budget policyEffect when the configured threshold or limit is reached
Hard BlockBlocks requests once the applicable budget limit is exceeded.
Warning OnlySends a warning notification when the limit is exceeded.
ThrottleReduces requests per minute when the configured threshold is exceeded.

Review all affected members before using a bulk change. Switch to Team Budget removes the personal budget. Saving automatic downgrade rules can affect routing immediately when the current usage has already reached a configured threshold.

API Keys → Active, Expired, or Revoked

Review and revoke user virtual keys

Users receive their gateway virtual keys through gateway-cli after Cognito sign-in. The API Keys page shows key records and provides revocation.

  1. Choose Active, Expired, or Revoked. Match the owner and the visible key prefix when investigating a specific credential.
  2. For an active key that you intend to invalidate, select Revoke and verify the prefix in the confirmation dialog.
  3. Confirm only after identifying the intended key. Check the Revoked view after the action. If the account still needs access, have the user follow the approved CLI sign-in flow.

Revocation makes the key unusable immediately and cannot be undone. The development capture had no active keys, so it shows the status lists.

Agents → Issue long-lived key or select an agent

Manage credentials for service accounts

Agents manages server-side identities and their long-lived gateway virtual keys. The account is created in Cognito before an administrator selects it for issuance.

  1. Open Issue long-lived key. Select the intended account and review the lifetime and existing-key status in the form.
  2. After authorized issuance, place the new credential in the application’s approved secret store and deploy or reload the application as needed. Use the key as a Bearer credential. Keep its full value out of logs, tickets, and documentation.
  3. Open the agent detail to review Cost and Tokens for the selected period. The detail view also identifies usage that could not be attributed to a specific key when applicable.
  4. If an application gets 401 while the key is still valid, check the configured secret and current key status. Use Repair auth when the cause is a lost key-to-account mapping and the action is available.

Issuing a replacement expires the previous key immediately. Plan the application’s secret update before issuing the replacement, then verify that the application can make an authenticated request.

Monitoring → Usage log

Investigate request failures and latency

Use Monitoring for individual gateway events. Start with the request time and type, then use the request ID to correlate the client report with the gateway event.

  1. Open Monitoring and locate Usage log. Choose a Type such as Error, Timeout, Cancelled, Slow, or Abnormal. Abnormal groups errors, timeouts, and slow requests.
  2. Record the request ID and compare the status, timing, app, and model with the incident details when those fields are available. Confirm whether the issue is isolated or appears across multiple clients.
  3. Where request-body logging is enabled and authorized for the investigation, open View body logs. Use Sessions for session context or By request for a specific request. Narrow the view by time or client and verify the request before opening any payload.

Request bodies may contain user prompts, responses, and confidential data. The screenshots show metadata only. Use the minimum detail required for the investigation.

Analytics → Group By

Analyze consumption by model, team, or user

Use Analytics for comparisons and trends across a period. Keep the date range and aggregation consistent when comparing results.

  1. Choose the reporting period. Use Custom Range when you need start and end dates for a specific incident or reporting window.
  2. Switch Group By among By Model, By Team, and By User. Compare the request count, tokens, and cost shown for that view.
  3. In By User, select a chart label or expand the relevant user in the User × model token usage table to inspect the model breakdown. Use the token columns and sort order that match the reporting question.
  4. Open Export and choose the appropriate format where available. The observed menu includes CSV, JSON, and a user-by-model CSV. Record the timeframe and grouping with any shared report.

BI Insight

Ask questions about gateway usage

BI Insight provides a natural-language interface for usage and cost analysis when the capability is deployed.

  1. Open BI Insight. If the menu is missing, confirm the administrator role and the environment’s feature availability.
  2. State the metric, date range, and any relevant app or team. For example, ask which teams had the highest gateway usage cost last month and request a breakdown by app.
  3. Review the returned period and grouping. Cross-check totals and unusual findings against Analytics before sharing them or making a policy change.

Audit Log → Show details

Trace administrative changes

Audit Log shows recorded administrative actions. Use it to confirm who acted, when they acted, and which target or result was recorded.

  1. Choose a time window such as 24h, 7 days, or 30 days. Start with the shortest window that covers the event.
  2. Set Category, then Action where applicable. Use the actor search when you know who made the change.
  3. Select Show details on the matching entry. Review the event time, actor, action, and target. Open Raw JSON when you need the exact recorded fields.
  4. Compare the event to the corresponding configuration or incident window. Share only the audit fields needed for the case.

Integration → Claude, OpenAI, or LangChain

Connect server-side applications

Choose the example that matches your application’s client library. Use the gateway endpoint and the alias registered for that API family.

  1. Open Integration and select Claude, OpenAI, or LangChain. Review the environment-specific values displayed on the page.
  2. Obtain an authorized long-lived virtual key through Agents. Store it in the application’s secret manager and load it at runtime as a Bearer credential.
  3. Use a gateway-registered alias. Use /v1/messages for Claude-family calls or /v1/chat/completions for OpenAI-family calls, according to the documented integration example.
  4. Run a minimal request with the intended alias. If it fails, check the gateway URL, current credential, endpoint and alias pairing, and the account’s effective access.

CLI → Operating system instructions

Install and configure gateway-cli

The CLI page provides operating-system-specific instructions for interactive users, Cognito login, and gateway setup.

  1. Open CLI and select the instructions for the target operating system. Check Binary Downloads for the package if one is available in the environment.
  2. Install the client using the instructions shown in the console. Run gateway-cli login and complete Cognito sign-in in the browser. The first successful CLI sign-in can provision the user and team from Cognito claims.
  3. Use the gateway URL shown for the environment with gateway-cli setup --gateway-url as instructed on the page. Run gateway-cli status to verify the resulting setup.
  4. Use gateway-cli logout to clear local sign-in state when required. If you are removing managed configuration, follow the page’s instructions for gateway-cli disable.

The captured development environment displayed no published download packages. If the page still shows none, obtain the approved build from the distribution owner.

Troubleshooting

SymptomChecks
Account signs in but registration failsVerify the identity-provider group assignment and gateway registration. Confirm the expected team and role in Users/Teams after the account is registered.
A console page returns 403Confirm the account role and environment. For a client request, inspect the app and model access of the affected user in Users/Teams.
An application receives 401Check the gateway URL, current secret and key status, and whether the key was rotated or revoked. For a valid agent key with a lost auth mapping, see Agents.
An alias is unavailableVerify the registered alias, active status, API family, and effective app and model policy. Check whether a default or fallback points to a deactivated model.
Requests are throttled or blockedCheck Rate limit at the affected scope, then review team and member budget utilization and enforcement in Budget Management.
Cost figures differ across viewsMatch time period, timezone, selected app, and report grouping. Check whether an amount includes web search before comparing it with model-only costs.
The cause is still unclearRecord the request ID, time and timezone, app, model alias, and status. Inspect Monitoring for the request and Audit Log for relevant changes. Keep credentials and request payloads out of the case summary.
