# 서버측 Web Search 는 어떻게 동작하나 (초보자용)

> 이 문서는 [install-guide.md §5](install-guide.md#5-서버측-web-search-us-east-1) 를 **개념부터** 이해하려는 사람을 위한 것이다. 설치 명령은 §5 에 있고, 여기서는 *"직원이 질문하면 무슨 일이 일어나나"* 만 그림으로 설명한다.

---

## 한 문장

**직원의 Claude Code 는 아무 설정도 안 한다.** 게이트웨이가 대신 웹 검색을 붙여주고, 검색이 필요한지는 **모델이 스스로 판단**한다.

---

## 가장 헷갈리는 것 먼저 — "어떤 단어가 검색을 켜나?"

**아무 단어도 아니다.** "지금"·"최신"·"now" 같은 키워드로 켜지는 게 **아니다.**

```
❌ 흔한 오해:   프롬프트에 "지금" 이 있으면 → 검색
✅ 실제:        게이트웨이는 web_search 툴을 "항상 테이블 위에 올려두고",
               쓸지 말지는 모델이 질문을 보고 스스로 정한다 (1P Claude 와 동일)
```

게이트웨이는 **프롬프트 내용을 읽지 않는다.** 그냥 툴을 제공만 하고, 판단은 모델 몫이다. 그래서 "지금" 이 없어도 검색하고("삼성전자 2분기 실적"), "지금" 이 있어도 안 할 수 있다("지금 몇 시야" → 모델이 자기 지식으로).

모델이 무엇을 보고 정하나 — 게이트웨이가 툴에 붙여주는 **설명문 한 줄**:

> *"Search the public web for **current, factual, or recent** information. Use this when the answer may depend on events, data, docs, or facts that are **recent or external**."*

이게 유일한 판단 근거다. "이럴 때 써라" 라고 가이드만 주고 결정은 모델에게 맡긴다.

---



## 전체 흐름 (직원이 질문 하나 던졌을 때)

```
   [ 직원 PC · Claude Code ]
        "삼성전자 어제 주가 알려줘"
        (직원은 web search 설정을 한 적이 없다)
              │
              ▼
   ┌───────────────────────────────────────┐
   │  gateway-proxy         (us-west-2)     │
   └───────────────────────────────────────┘
              │
              │  ① 이 앱(claude-code) 웹서치 토글 ON?   … §5-3
              │       · OFF → 그대로 통과 (아래 전부 skip)
              │       · ON  → web_search 툴을 요청에 붙임 (프롬프트는 안 읽음)
              ▼
   ┌───────────────────────────────────────┐
   │  ② 모델         Bedrock · us.anthropic │
   │     "질문 + web_search 툴이 여기 있음"  │
   └───────────────────────────────────────┘
              │
              │  ③ 모델이 스스로 판단
              │
      ┌───────┴─────────┐
      │                 │
  "내 지식으로       "최신/외부 정보
   답 가능"           필요"
      │                 │  web_search 호출
      │                 ▼
      │      ┌───────────────────────────────────────┐
      │      │  ④ gateway-proxy 가 호출을 가로챔       │
      │      │     SigV4 / IRSA (AWS_IAM)             │
      │      └───────────────────────────────────────┘
      │                 │
      │                 ▼
      │      ┌───────────────────────────────────────┐
      │      │  Amazon Bedrock AgentCore Gateway      │
      │      │  (MCP 엔드포인트, us-east-1)            │
      │      └───────────────────────────────────────┘
      │                 │
      │                 ▼
      │      ┌───────────────────────────────────────┐
      │      │  관리형 WebSearch 커넥터                │
      │      │  = Amazon 자체 웹 인덱스               │
      │      │    (Tavily · 구글 아님)               │
      │      └───────────────────────────────────────┘
      │                 │  검색 결과
      │                 ▼
      │        결과를 모델에게 되먹임
      │        └─ ③ 으로 되돌아가 최대 5회 반복
      │                 │
      └────────┬────────┘
               ▼
      모델이 최종 답 작성 (검색했든 안 했든)
               │
               ▼
   [ 직원 PC 화면 ]  하나의 매끄러운 답변
                     검색 티 안 남 — 1P Claude 처럼 자연스럽게
```

핵심 3가지:

- **①의 토글**만 운영자가 켜면 된다 (§5-3). 직원은 아무것도 안 한다.
- **③의 판단**은 모델이 한다. 키워드 규칙이 아니다.
- **④ 이후**는 전부 AWS 안 — gateway-proxy → **AgentCore Gateway** → 관리형 커넥터 → Amazon 웹 인덱스. 질의가 제3자(구글·Tavily)로 안 나간다.

---



## 왜 게이트웨이가 대신 하나 (직원이 설정 안 하는 이유)

Bedrock 은 Anthropic 의 네이티브 서버측 web search 를 **지원하지 않는다**. 그래서 게이트웨이가 그걸 **흉내낸다** — 툴을 주입하고, 모델의 호출을 가로채 AWS 검색을 부르고, 여러 번 오간 대화를 **하나의 답변으로 봉합**한다. 직원 눈에는 그냥 Claude 가 알아서 검색해 답한 것처럼 보인다.

이 "흉내" 를 매끄럽게 하려고 두 가지 잠복 버그를 고쳤다(네이티브 툴 정리·thinking 봉합). 상세는 [install-guide.md §6](install-guide.md#6-클라이언트-설치--claude-code-awsome-gateway-cli) 도입부와 fork `us/deploy-fixes`.

## 멈추는 조건 (무한 검색 방지)

모델이 검색→읽기→또 검색을 반복할 수 있어서 상한이 있다:


| 상한    | 기본값     | 뜻                                         |
| ----- | ------- | ----------------------------------------- |
| 검색 반복 | **5회**  | 한 질문에 최대 5번까지 검색하고, 그 뒤엔 툴을 빼서 모델이 답하게 강제 |
| 전체 마감 | **90초** | 이 시간을 넘으면 더 검색 안 하고 답한다                   |


튜닝은 [§5-5](install-guide.md#5-5-업데이트-무엇을-바꾸느냐에-따라--대부분-재프로비저닝-불필요) (선택).

---



## 검증 — "정말 검색했나?"

🔴 **로그로 확인하려 하지 말 것.** 성공한 검색은 **로그를 한 줄도 안 남긴다.** 확인은 두 가지:

- **CloudWatch** — AgentCore 게이트웨이의 `tools/call` 호출 수 (DB·비번 불필요). 명령은 [§5-4](install-guide.md#5-4-검증-6-클라이언트-설치-후).
- **DB** — `usage.usage_logs.web_search_count` (성공한 검색만 카운트).

> **왜 로그가 없나**: 성공 경로엔 로그 코드가 없다. 실패했을 때만 warning 이 찍힌다. 그래서 `kubectl logs | grep web_search` 는 **정상 동작해도 빈 출력**이라 "안 된다" 고 오해하기 쉽다.

## 한눈에 (요약 카드)


| 질문             | 답                                                   |
| -------------- | --------------------------------------------------- |
| 직원이 설정하나?      | **아니다.** 운영자가 토글만 켠다(§5-3).                         |
| 어떤 단어가 검색을 켜나? | **없다.** 모델이 스스로 판단.                                 |
| 검색은 어디서?       | **AWS 관리형**(us-east-1). 구글·Tavily 아님.               |
| 질의가 밖으로 나가나?   | **아니다.** AWS 안에서 처리(zero egress).                   |
| 몇 번까지 검색?      | 기본 **5회 / 90초**.                                    |
| 검색했는지 확인은?     | **CloudWatch** `tools/call` 또는 `usage_logs`. 로그 아님. |
