# Budget Management 룰 명세

> **NDS 전용 명세** (upstream 대상 아님). 팀 → 유저 → 앱 3계층 예산 모델의
> 비즈니스 룰을 정의합니다. 구현은 별도 작업으로 진행하며, 이 문서가 기준입니다.
>
> 상태: **확정안 v4** (구현 전)

## 0. 용어

| 기호 | 의미 |
|---|---|
| `T` | 팀 예산 (월간, USD) |
| `A_u` | 유저 u의 할당(예약) 예산 |
| `ΣA` | 팀 내 유저 할당 합계 |
| `U` | 유저 총예산 (= `A_u`) |
| `app_c` | 유저의 클라이언트별 예산 (`claude-code` / `cowork` / `codex`) |
| `usage` | 해당 월 실제 사용액 (KST 월 경계, `YYYY-MM`) |

## 1. 계층 모델

```
TEAM (pool T)  ── 팀 전체 월간 상한 + 유저 예약의 원천
 └─ USER (A_u) ── 풀의 예약분 = 해당 유저의 개인 상한
     └─ APP (app_c) ── 유저 예산 내 개별 cap (예약 아님)
```

- **POOL 모델만 지원.** "균등분배"는 모드가 아니라 일회성 bulk 액션 —
  모든 멤버에게 `T/N`을 일괄 쓰기(기존 allocate API 재사용).
  이후 개별 조정은 자유.
- 유저 할당은 **예약(reservation)**: 설정된 금액은 풀에서 떼어져
  다른 유저가 쓸 수 없다.
- 미할당 유저는 **잔여 풀**을 공유한다.

## 2. 불변식 (항상 참이어야 함)

| # | 규칙 |
|---|---|
| I-1 | `ΣA ≤ T` — 유저 할당 합계 ≤ 팀 예산. **ADMIN 포함 모든 역할에 강제** |
| I-2 | `Σapp_c ≤ U` — 명시된 앱 예산 합계 ≤ 유저 총예산 |
| I-3 | `A_u ≥ 0`, `app_c ≥ 0`, 음수 불가 |
| I-4 | 앱별 예산은 부모 유저 예산이 있을 때만 생성 가능 (현행) |
| I-5 | 유저 예산은 해당 팀 멤버에게만 설정 가능 (팀 소속 검증 — 현재 allocate에서 누락된 검사 추가) |

## 3. 팀 예산 규칙

### 설정/수정 — ADMIN 전용

- `T` 설정 시 모드 선택 UI 없음 (POOL 고정), 화면에 "Pool" 표시
- **증액**: 항상 허용. 할당 유저는 유지, 잔여 풀(`T - ΣA`) 증가 →
  미할당 유저 cap 자동 상승
- **감액** — 경우의 수:

| 케이스 | 조건 | 처리 |
|---|---|---|
| ① 미할당 | `ΣA = 0` | 허용. `usage > T_new`면 경고: "현재 사용량이 예산을 초과하여 팀 전체가 차단됩니다" |
| ② 부분/전체 할당, 여유 | `ΣA ≤ T_new` | 허용. 할당 유저 유지, 미할당 cap = `T_new - ΣA`로 자동 축소. `usage > T_new`면 동일 경고 |
| ③ 할당 초과 | `ΣA > T_new` | **거부** + 알림: "유저 할당 합계($X)가 새 예산을 초과합니다. 먼저 유저 예산을 줄이세요." — `ΣA`, `T_new`, 초과액 표시 |

- 팀 예산 삭제(해제) — 현행 유지: 팀 예산 없으면 해당 팀 요청은
  `team_budget_unset` 차단

## 4. 유저 예산 규칙

### 설정/수정/삭제 — ADMIN + TEAM_LEADER(자기 팀만)

- 한 번에 한 명씩 변경 (bulk은 allocate 액션)
- **입력 상한** = `T - Σ(타인 할당)` — UI에 실시간 표시.
  본인 기할당분은 재조정 가능 (cap = `T - ΣA + A_u`)
- **미할당 유저의 effective cap = `T - ΣA_u`** — 요청 시점에 유저 단계에서도
  적용 (현재는 유저 config 없으면 pass-through → **변경 필요**)
- **삭제** = 예약 해제 → 잔여 풀 복귀. ADMIN + TEAM_LEADER(자기 팀) 모두 가능
- 팀 소속이 아닌 유저에 대한 설정은 거부 (403)

### 균등분배 액션

- "균등분배" 버튼 → 모든 현재 멤버에게 `T/N` 쓰기
  (기존 할당 덮어씀 여부는 액션 옵션 — 구현 시 UI에서
  "기존 할당 유지/덮어쓰기" 선택)
- 결과는 평범한 유저 예약들일 뿐, 이후 규칙은 POOL과 동일

## 5. 앱별 예산 규칙

- `app_c` = 유저 총예산 `U` 안의 **개별 cap**
  (예약이 아님 — 미설정 앱과 공유됨)
- 설정된 앱 예산의 합 `Σapp ≤ U` 강제
- UI 입력 상한 = `U - Σ(다른 앱)` — 예: `U=$3`, `claude-code=$3` →
  cowork/codex 입력 상한 자동 $0 (여유가 없다는 뜻, 차단 아님)
- **미설정 앱** = 개별 cap 없이 유저 총예산 `U`까지 사용 가능 (현행 유지).
  단 모든 사용량은 `U`에 합산
- 유저 예산 `U` 감액 시 `Σapp > U_new`가 되면 → 거부 + 알림
  (팀 감액 ③과 동일 패턴)

## 6. Enforcement (요청 시점, gateway-proxy)

요청당 순서대로 — 하나라도 걸리면 429:

1. **유저 단계**: `user_used < cap_u`
   where `cap_u = A_u` (할당됨) 또는 `T - ΣA` (미할당)
2. **팀 단계**: `team_used < T`
3. **앱 단계**: 해당 client의 `app_c`가 설정된 경우 `app_used < app_c`
4. 각 단계에 정책 적용: `HARD_BLOCK`=100% 차단 ·
   `SOFT_WARNING`=~110% 허용+경고 헤더 · `THROTTLE`=차단 없이 RPM 감소 (현행)

- 캐시 무효화: 팀/유저/앱 예산 변경 시 관련 키 전부 무효화 — 특히
  **ΣA에 의존하는 미할당 cap은 팀 멤버 누구의 예산 변경에도 영향받으므로,
  유저 예산 변경 시 같은 팀 멤버들의 config 캐시 갱신 필요**
  (구현 시 핵심 포인트)

## 8. 현행 대비 변경이 필요한 부분 (구현 대상)

| # | 현재 | 변경 |
|---|---|---|
| D-1 | ΣA≤T 검증이 리더만 적용 (`set_user_budget` admin 우회) | 전원 강제 |
| D-2 | `allocate`가 팀 소속 검증 누락 | I-5 검증 추가 |
| D-3 | 미할당 유저는 유저 단계 무제한 | effective cap = `T - ΣA` enforcement |
| D-4 | 앱 예산 합계 검증 없음 | `Σapp ≤ U` 추가 |
| D-5 | 유저 예산 삭제 ADMIN 전용 | 리더 자기 팀 허용 |
| D-6 | 팀 감액 검증 없음 | 케이스 ①②③ 처리 (거부+알림 / 경고) |
| D-7 | UI에 입력 cap 없음 | 실시간 상한 표시 (유저·앱 입력) |
| D-8 | UI에 Pool 표시 없음 | 모드/풀 상태 표시 |

## 9. 유보 사항 (명시적 미결)

- 유저의 팀 이동: 개인 예산·사용량은 유저 귀속 (현행).
  이관 시 새 팀 ΣA 검증은 별도 결정 사항으로 유보
- 팀 없는 유저의 요청 동작: 현재 `team_budget_unset`과 유사하게
  차단될 가능성 — 구현 전 확인
- TEAM_LEADER의 downgrade 규칙 쓰기 권한: 유보 (현재 ADMIN 전용)
- 조직/부서 상위 예산 계층: 없음 (필요 시 TEAM 위에 추가)
