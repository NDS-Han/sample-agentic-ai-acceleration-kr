# 새 beta 조사 — 실사용자 Claude Code 가 더 보내는 것

> 작성 2026-10-09 · Claude Code 2.1.294(실사용자 Mac, 개발 게이트웨이 로그) · 2.1.295(로컬 캡처) · Bedrock us-west-2 직접 호출

## 요약

Claude Code 2.1.294~2.1.295 가 게이트웨이로 보내는 beta 를 다시 조사했습니다. 새로 보이는 6개 가운데 2개가 지금 게이트웨이에서 400 을 내고, 게이트웨이 결함도 하나 찾았습니다.

- 빈 설정의 Claude Code 2.1.295 는 2026-10-05 와 같은 beta 11개를 보냅니다. 계정 기능 플래그가 켜진 실사용자는 6개를 더 보냅니다.
- 그중 2개가 지금 게이트웨이에서 대화마다 400 을 한 번 냅니다. Claude Code 가 그 기능을 빼고 다시 보내므로 장애는 아닙니다.
  - `thinking-display-updates-2026-08-18`: `thinking.display: "updates"` 가 400 입니다. 개발 게이트웨이에서 실제로 났습니다.
  - `inline-tools-2026-09-15`: system 메시지의 `tool_addition` 블록이 400 입니다. 로컬에서 재현했습니다.
- 두 beta 모두 Bedrock(Sonnet 5.5·Opus 5.5)이 받아들이고 기능도 동작합니다. 공식 문서는 `inline-tools` 를 Claude API 전용으로 적고 있지만 Bedrock 에서도 됩니다.
- 게이트웨이 결함이 1건 있습니다. advisor 도구는 지우지만 그 도구를 가리키는 `tool_addition` 블록은 남겨서, beta 를 넘겨도 400 입니다.
- 대응은 아직 정하지 않았습니다(3-3).

## 이 문서를 읽는 이유

- 게이트웨이 로그에 `thinking.adaptive.display` 나 `tool_addition` 400 이 보일 때
- `inline-tools`·`thinking-display-updates` 를 넘길지 정할 때(3-3)
- 게이트웨이가 만드는 400 이 Auto mode 서버 판정에 어떤 영향을 주는지 알고 싶을 때(3-2)

## 1. 배경 — 누가 무엇을 보내나

| 보낸 쪽 | beta 수 | 근거 |
|---|---|---|
| 2.1.295, 빈 설정(`CLAUDE_CONFIG_DIR`) | 11 | 로컬 캡처, 2026-10-05 와 같음 |
| 실사용자 2.1.294 (계정 플래그 켜짐) | 11 + 6 | 개발 게이트웨이 `beta_dropped` 로그 |
| 2.1.293, Anthropic API 직접 | 20 | 게이트웨이 경로와 목록이 다름 |

새 6개: `inline-tools`, `thinking-display-updates`, `advisor-tool`, `redact-thinking`, `structured-outputs`, `fallback-credit`.

## 2. 결과

### 2-1. Bedrock 시험

| beta | 이름 하나만 넣은 요청 | 기능 |
|---|---|---|
| `inline-tools-2026-09-15` | 200 (Sonnet 5.5·Opus 5.5·Haiku 4.5·Sonnet 5·Opus 5) | `tool_addition` 동작 (아래) |
| `thinking-display-updates-2026-08-18` | 200 | beta 가 있으면 `display: "updates"` 200, 없으면 400 |
| `structured-outputs-2025-12-15` | 200 | 시험 안 함 |
| `fallback-credit-2026-06-01` | 200 | 시험 안 함 |
| `advisor-tool-2026-03-01` | 400 | — |
| `redact-thinking-2026-02-12` | 400 | — |

### 2-2. `tool_addition` — 대화 중간에 도구를 더하는 블록

2.1.295 는 대화 중간 system 메시지에 이런 블록을 넣었습니다(실제 캡처).

```json
{"role": "system", "content": [
  {"type": "text", "text": "…"},
  {"type": "tool_addition", "tool": {"type": "tool_reference", "name": "advisor"},
   "cache_control": {"type": "ephemeral"}}]}
```

Sonnet 5.5 와 Opus 5.5 의 결과는 같았습니다.

| 블록의 도구 | 넘긴 beta | 결과 |
|---|---|---|
| `tool_reference`(이름만) | `inline-tools` | 200 |
| `tool_reference` | `mid-conversation-tool-changes` | 200 |
| `tool_definition`(정의 전체) | `inline-tools` | 200, 새 도구를 실제로 호출 |
| `tool_definition` | `mid-conversation-tool-changes` | 400 (`tool_reference` 만 허용) |
| 둘 다 | 없음 | 400 (`tool_addition` 을 모름) |

Haiku 4.5 는 대화 중간 system 메시지 자체가 400 입니다(2026-10-05 와 같음).

### 2-3. 게이트웨이를 거친 실제 요청

캡처한 요청을 gateway-proxy 라우터에 넣어 Bedrock 으로 나갈 본문을 만든 뒤, 그 본문을 Bedrock 에 보냈습니다(Sonnet 5.5).

| 경우 | 결과 |
|---|---|
| 게이트웨이 출력 그대로 | 400 `Input tag 'tool_addition' found using 'type' does not match any of the expected tags` |
| `inline-tools` 를 더 넘김 | 400 `tool_addition/tool_removal references unknown tool 'advisor'` (게이트웨이가 advisor 도구를 지웠기 때문) |
| `tool_addition` 블록만 지움 | 200, 판정(`safeguard_results`) 있음 |
| `inline-tools` 를 넘기고 블록이 남은 도구를 가리킴 | 200, 판정 있음 |

### 2-4. `thinking.display: "updates"`

개발 게이트웨이에서 2026-10-08 13:23 UTC 에 실제로 났습니다. 스트리밍 요청이 400(`thinking.adaptive.display: Input should be 'summarized', 'omitted'`)을 받았고, 비스트리밍으로 다시 보낸 요청도 400 이었습니다. 그 뒤 Claude Code 가 display 를 빼고 보내 성공했습니다.

## 3. 의미

### 3-1. Claude Code 의 자동 복구

Claude Code 프로그램 안의 경고 문구와 로컬 재현으로 확인했습니다.

- `tool_addition` 400: `[late-tool-additions] tool_addition rejected (block_type_unknown)` 경고를 남기고 블록과 beta 를 빼고 다시 보냅니다. `/clear` 나 `/compact` 전까지는 다시 넣지 않습니다. 도구는 다른 방법(ToolSearch 안내)으로 알립니다.
- `display: "updates"` 400: `[thinking] a request was refused with thinking.display 'updates' …` 경고를 남기고, 그 대화에서는 다시 보내지 않습니다.
- 웹 검색 경로에서는 오류가 HTTP 200 + `event: error` 로 가므로, Claude Code 가 먼저 비스트리밍으로 다시 보내고 그 400 을 받은 뒤에 복구합니다. 첫 턴이 조금 느려집니다.

### 3-2. ⚠️ 서버 판정이 꺼지는 조건

위 두 400 은 Claude Code 가 알아보는 오류라 해당하지 않습니다. 그 밖의 400 이 서버 판정 beta(`dangerous-tool-use`)가 실린 요청에 오면 다음과 같이 처리합니다.

```text
[server-classifier] an unrecognised HTTP 400 arrived while the dangerous-tool-use
beta was on the request; retrying once without it, and auto mode decides with the
local classifier for the rest of this conversation
```

그 대화는 끝까지 PC 쪽 분류기를 쓰고, 별도 분류기 요청과 과금 안내가 다시 생깁니다. 게이트웨이가 새로 만드는 400 은 이 경로로 서버 판정을 조용히 끌 수 있습니다.

### 3-3. 대응

아직 정하지 않았습니다. 검토 중인 수정은 다음과 같습니다.

- `BEDROCK_FORWARD_BETAS` 에 `inline-tools-2026-09-15`, `thinking-display-updates-2026-08-18` 를 더합니다.
- advisor 도구를 지울 때 그 도구를 가리키는 `tool_addition`·`tool_removal` 블록도 지웁니다. 그 결과 비게 되는 system 메시지도 처리합니다.
- `display: "updates"` 는 응답 블록의 모양이 달라질 수 있어, 웹 검색 루프가 그대로 처리하는지 확인이 필요합니다.

## 4. 시험 방법

- **캡처:** 받은 요청을 파일에 쓰고 짧은 SSE 응답을 돌려주는 로컬 서버에 Claude Code 를 붙였습니다(`ANTHROPIC_BASE_URL=http://127.0.0.1:<포트>`, 가짜 토큰). 계정 플래그의 영향을 빼려면 빈 설정 폴더(`CLAUDE_CONFIG_DIR`)로 실행합니다.
- **게이트웨이 변환:** 캡처한 본문을 gateway-proxy 라우터에 넣고(Bedrock 은 가짜) Bedrock 으로 나갈 본문을 받았습니다. 회귀 테스트 `tests/regression/test_high_bedrock_beta_forwarding.py` 의 도우미를 그대로 썼습니다.
- **복구 동작:** 같은 로컬 서버가 `tool_addition` 이 든 요청에 게이트웨이와 같은 형식의 400 을 돌려주게 하고, Claude Code 가 다시 보내는 요청을 봤습니다.
- **실사용 근거:** 개발 게이트웨이 로그의 `upstream_compat.beta_dropped` 와 `bedrock_stream_client_error` 입니다.
- **규모와 비용:** Bedrock 호출 약 40건, 1달러 미만입니다.
